# PageNest

本地优先、模块化的智能文档处理工作站。PageNest 面向桌面浏览器，将文档工具组织在统一、简洁的工作区中。

**当前本地版本：v0.2.0 · Phase 3A**

## 当前可以做什么

- 访问工作台、格式转换、文件压缩、PDF 页面管理、OCR、任务记录和设置。
- 工作台及通用工具页面支持选择或拖放文件，查看名称、类型和大小等基础信息，不读取文档内容。
- 在 PDF 页面管理中独立导入一个或多个真实 PDF，解析实际页数，浏览按需渲染的页面缩略图，并查看页面尺寸与方向。
- 切换 PDF、选择页面、移除文件或清空 PDF 工作区。同名文件分别保留，批量导入中单个文件失败不会阻止其他文件。
- 在单份 PDF 内多选、删除、调整页面顺序和旋转页面，并分别撤销或重做每份文档的编辑。
- 将当前单份 PDF 的全部保留页面按编辑后的顺序和旋转生成新 PDF，验证后下载；允许修改导出文件名。
- 导出当前选中的页面；按指定文档顺序合并多个 PDF；按当前页码范围或每 N 页拆分，分别验证并下载结果。
- 在文件压缩页面执行 PDF 内容保持型优化，或按三档质量重编码安全支持的 JPEG 图像，验证后逐份下载。
- 切换浅色、深色、跟随系统主题，并在本机保存主题偏好。

单个文件最多 100 MiB（104,857,600 字节），最多保留 20 个文件。PDF 工作区另有累计 256 MiB、每份 PDF 最多 1,000 页的限制，以控制浏览器内存占用。容量按 1024 进制计算；通用文件列表沿用 KB、MB 标签，其中 MB 对应 MiB（1024² 字节），KB 对应 KiB（1024 字节）。

PDF 页面管理提供当前文档、选中页面、文档顺序合并和范围拆分四种输出方式，文件压缩独立提供 PDF 优化。暂未提供跨文档页面交错拖拽、PPTX 压缩或 ZIP 批量下载。文档转换、OCR、任务处理和全局搜索尚未开放。

PDF 页面管理与文件压缩各自只在当前浏览器会话内存中保留所选文件，离开对应页面、刷新或关闭时清除。工作台和其他通用工具继续只保存文件元数据，不会自动传递为已解析 PDF。应用不上传文档，不将文件内容或文件列表写入 localStorage 或 IndexedDB；只有主题偏好保存在本地。页面、Worker、字体等静态资源仍由网站托管方提供。

## PDF 压缩

打开文件压缩，选择或拖入 PDF，选择处理方式后开始。多文件逐份串行处理，显示读取、优化、独立验证和下载就绪等真实阶段；每份结果独立下载。原文件不会被覆盖，压缩列表与页面编辑器互相隔离。

- **无损优化**是内容保持型结构优化：重新封装 PDF 对象流，对单 Flate 流使用浏览器原生 `DecompressionStream` / `CompressionStream` 重压缩，仅替换更小的流并保留预测器参数。不降低图像质量，不删除页面、文字或矢量，不主动删除作者、书签和元数据；它不等于字节级无损。
- **高质量 / 均衡 / 较强**分别使用 JPEG 质量参数 **0.88 / 0.72 / 0.50**，保持原像素尺寸。只重编码可安全检查的 8-bit DeviceRGB 基线 JFIF JPEG XObject。ICC/Exif/CMYK JPEG、蒙版、特殊解码参数等对象会跳过；图层或透明混合上下文会拒绝有损处理。文字、OCR 文字层、其他图像及矢量不转为整页截图。

比例按 `(原始字节数 - 输出字节数) / 原始字节数 × 100%` 计算。体积相等或增加时显示“此 PDF 已较为紧凑，本次优化未获得更小的文件。”及实际大小/比例，不称为压缩成功，也不保留更大的文件供下载。已压缩 PDF、照片或某些扫描件可能没有收益。

结果由独立 PDF.js 重新打开，严格检查页数、几何、旋转、文字、作者等元数据及书签语义。无损模式逐页比较 128/512 像素渲染摘要；有损模式重新解析全部非目标对象图、检查实际 JPEG 质量，并把目标图像替换成相同中性图后对非图像内容执行两种分辨率的严格渲染比较，正常页面另需通过分档 PSNR 门槛。任何检查、解析或清理失败都不提供下载。这些检查不能证明所有高分辨率细节及全部交互语义完整保留。

压缩限制为单文件 **32 MiB**、最多 **5 份**、累计输入 **96 MiB**、每份 **200 页**、累计保留结果 **64 MiB**。Flate/原始流单条最多展开 **16 MiB**、累计 **64 MiB**；图像最多 **100 个**，源图每图最多 **800 万像素**、累计 **3200 万像素**，分量数据估计单图 **64 MiB**、累计 **128 MiB**。JPEG 重编码另限制每图 **400 万像素**、边长 **4096**。这些是分层保护，不是完整浏览器堆内存的硬上限；解析器初次展开对象流、图像解码及垃圾回收仍可能占用更多内存，大型复杂 PDF 的峰值压力测试尚未完成。

压缩预检会拒绝可识别的加密、数字签名、表单、附件、活动内容，以及无法有界检查的 JPEG2000/JBIG2/CCITT、Separation/DeviceN/未知嵌套色彩空间、冲突短键、多重滤镜和内联图像等结构。其他特殊结构也不保证全部保留；重要文件应保留原件并用独立阅读器复核。

重计算在懒加载的模块 Worker 中执行，单文件最多等待三分钟。取消、移除、清空或离页会终止所属 Worker，使晚到结果失效并释放缓冲/Blob URL；下载 URL 最迟 60 秒撤销。没有 WASM 虚拟文件系统或服务器 PDF API。技术验证评估过 qpdf WASM 的许可、版本及嵌入依赖风险，正式方案复用既有 pdf-lib、PDF.js 和原生浏览器 API，**不新增运行时依赖、不通过 CDN 加载引擎**。PDF.js 自身的辅助 WASM 仍由站点同源提供。

## PDF 工作区

从左侧导航打开 PDF 页面管理，点击添加 PDF 或拖入文件。左栏管理文件，中间浏览真实缩略图，右栏显示所选文档及页面信息。缩略图通过页面可见性检测按需加载，限制渲染并发与 Canvas 像素尺寸，避免一次渲染全部页面。文件切换会取消不再需要的缩略图任务；移除文件、清空工作区及离开页面会释放对应解析任务、文档资源与 Canvas。

单击选择一页；Ctrl / Command + 单击添加或取消选择，Shift + 单击选择连续范围。在页面网格内按 Ctrl / Command + A 全选，Esc 取消选择。删除及旋转可以批量执行，至少保留一页。鼠标拖拽仅支持单页排序，多选时禁用拖拽；也可对单页使用“向前移动一页”和“向后移动一页”按钮。页面编号代表当前顺序，检查器同时保留原始来源页码。

撤销使用 Ctrl / Command + Z；重做使用 Ctrl + Y 或 Ctrl / Command + Shift + Z。编辑快捷键只作用于 PDF 页面网格及相关编辑控件，不接管输入框或其他页面。每份文档独立保存最多 50 步编辑历史，批量操作算作一步；撤销后执行新编辑会清除重做分支。切换文件保留各自的选择和历史。

编辑模型只保存页面来源、顺序、旋转与选择信息，不修改原始 PDF，也不为每次撤销复制二进制数据。旋转会叠加 PDF 原有旋转属性，排序不会重新解析文件。当前修改仅保存在浏览器工作区，需主动导出才会生成新文件；移除文件、清空工作区、离开 PDF 页面或刷新会丢弃编辑及历史。

### 单文件导出

选择已解析的 PDF，点击“导出 PDF”，核对保留页数、来源文件及兼容性说明，再修改文件名并点击“生成 PDF”。默认名称为 `原文件名_edited.pdf`，下载前会清理路径分隔符、Windows 非法字符、控制字符、保留名称和重复扩展名。导出包含该文档的全部保留页面，与当前选区无关。

“导出选中页面”只包含当前选区，按编辑器中的页面顺序输出，与点击选择的先后无关。Ctrl / Command 多选、Shift 连选和非连续选页均保留稳定页面来源及当前旋转；无选择时不能生成。

### 合并与拆分

从检查器打开“合并”，勾选至少两份已就绪文档，用上移、下移调整文档顺序，再核对输出计划。合并包含每份文档当前保留的页面，应用各自已有的删除、重排和旋转；同名文档通过独立 ID 区分。基础合并按文档分组，不提供跨文档交错页面队列。

从检查器打开“拆分”，选择自定义范围或每 N 页。页码基于当前编辑后的顺序，例如 `1-3,5,8-10` 生成三份独立 PDF，而不是一份不连续选页 PDF；需要单份不连续结果时请使用“导出选中页面”。每个范围内按当前顺序输出，逗号分隔的范围保留输入先后，重复、重叠、越界、反向或空范围均拒绝。每 N 页模式保留末尾不足 N 页的一组。输出使用唯一的 `_part-01.pdf` 等名称。

输出计划在点击生成时深复制并冻结，包含来源文档 ID、稳定页面 ID、原始页码和旋转增量。后续编辑不会改变正在生成的映射；移除任一参与文档、清空或离开工作区会使任务和待下载结果失效。一个工作区只运行一项输出任务，多份拆分结果串行生成；全部结果通过独立校验后才显示逐份下载按钮，任何一份失败会丢弃本批结果，不自动触发连续下载。

每项计划最多使用 20 份来源文档，输入累计不超过 128 MiB，输出累计最多 1,000 页、50 份 PDF，单份及全部保留结果累计不超过 100 MiB。超限会明确失败，不截断页面。各份输出都重新打开实际来源和结果，用 PDF.js 按来源绑定严格验证文字、像素、页数、尺寸和旋转。

多来源字体、图像和继承资源分别在来源上下文中复制，不共用源对象编号。基本可选图层的默认 ON/OFF 状态与显示顺序会合并，同时保持同名图层的独立引用；含替代配置、Usage/AS、互斥组或其他无法可靠组合的复杂图层结构会明确拒绝合并。单文件路径保持原有严格校验，不能据页面复制成功就认为内容完整。

界面按实际处理显示准备、生成、验证和下载就绪，不显示估算百分比。验证完成后点击“下载 PDF”，反馈仅表示“已生成 PDF 并触发下载”；应用无法确认浏览器是否已保存到磁盘或选择了哪个目录，请检查下载列表。导出不会覆盖原文件，也不会改变选区、编辑状态及撤销/重做历史。每次生成采用点击时的编辑快照，之后的新修改需要重新生成。

生成使用稳定来源页码，按当前顺序复制页面并设置归一化后的原始旋转加编辑旋转。下载前通过 PDF.js 独立重新解析输出，逐页核对数量、顺序对应的文字摘要与低分辨率实际渲染摘要、旋转、尺寸及方向；任何检查失败均不提供下载。这是保守的结构与视觉检查：相同视觉页面无法仅凭渲染区分，128 像素长边的比较不能证明所有细节或文档级结构完整。字体或特殊渲染差异可能导致拒绝导出。

验证失败会区分页数（`PAGE_COUNT_MISMATCH`）、尺寸/方向（`PAGE_GEOMETRY_MISMATCH`）、旋转（`PAGE_ROTATION_MISMATCH`）、文字（`TEXT_CONTENT_MISMATCH`）、渲染（`VISUAL_CONTENT_MISMATCH`）、检查异常（`INSPECTION_FAILURE`）和超时（`VALIDATION_TIMEOUT`）。提示仅包含固定诊断代码、检查阶段、页码、比较项目、像素差异的汇总数字和结构比较的布尔值，不包含正文、提取文字、原始像素、文件路径或内容摘要。视觉失败时可用重新解析及字体加载配置对照辅助定位；这些诊断不会单独允许下载。结构比较以生成库解析的对象为依据，不能替代 PDF.js 对原文件和输出的独立文字与渲染检查。报告问题时可只提供安全诊断字段；检查异常、超时或像素差异本身不代表文档已经损坏。无法确认完整性时仍不提供下载。

**PageNest 将尽量保留页面的视觉内容，但重新生成 PDF 可能影响签名、表单、书签和其他特殊结构。** 当前未可靠逐项识别数字签名、AcroForm、XFA、书签/大纲、注释、附件、JavaScript 动作和特殊元数据，不能保证这些结构保留或仍然有效，也不承诺严格无损导出。重要文件应另存原件并在适合的阅读器中复核。需要密码的 PDF 仍不支持。

原始 File 只保留在当前工作区，生成时临时重读，生成结束后擦除该临时缓冲。输出验证会以相同默认配置分别新建原文件和生成结果的 PDF.js 解析句柄，逐页严格比较；不复用已有缩略图渲染历史的预览句柄，也不使用像素容差。视觉失败后的诊断可额外在本地重读并复核，不改变预览配置；关闭 FontFace 的对照中，字体缺失时 PDF.js 仍可能使用替代字体，因此该对照不等于独立阅读器验证。临时解析句柄及 Canvas 会在各阶段结束后清理，独立解析和失败诊断会增加耗时与内存占用。结果字节与 Blob URL 不进入 React 状态或持久存储。切换文档、关闭导出面板、移除文件、清空或离开工作区会丢弃待下载结果；下载触发后 URL 最迟在 60 秒后释放。浏览器的垃圾回收时机不由应用控制。

每个工作区只允许一个导出任务。停止等待会使结果失效，但 pdf-lib 的解析和保存不能保证立即中断，需等待当前阶段返回后释放任务；期间不能启动另一项导出。任务在 5 分钟后请求终止，仍需等待安全阶段返回，不能保证总等待时间；每页验证另有超时限制，输出也限制为 100 MiB。生成仍在主线程执行，复杂或大型 PDF 可能短暂阻塞界面，并产生源数据、复制对象和输出的临时内存峰值；100 页人工样本不代表接近容量上限的复杂文件性能。验证逐页串行使用有限像素 Canvas，不触发全部 UI 高分辨率缩略图。

导入会检查文件特征，并由 PDF.js 真实解析。空文件、伪装 PDF、损坏文件、超限文件及解析或渲染失败都会显示明确提示。需要密码的 PDF 暂不支持；对于超出当前浏览器处理能力的文档，应使用更小的文件。复杂文档的字体、色彩和特殊 PDF 特性可能受浏览器及 PDF.js 支持程度影响。

## 功能规划

| 模块         | 后续方向                                                            |
| ------------ | ------------------------------------------------------------------- |
| 格式转换     | PDF、Word、PowerPoint、Excel 之间的实用转换，区分视觉保真和可编辑性 |
| 文件压缩     | PPTX 严格无损优化、视觉优化，以及更多 PDF 图像编码支持              |
| PDF 页面管理 | 跨文档页面交错排序、ZIP 批量下载及更多页面导出方式                  |
| OCR 智能识别 | 扫描文档识别、关键词定位和可搜索化；可搜索不代表完全可编辑          |
| 任务与工具箱 | 批量处理、任务队列、图片与表格提取、多步骤工作流                    |

简单任务计划优先在浏览器执行；高级能力可通过可选的 Windows 本地 Python / FastAPI 引擎提供。转换质量与可编辑性取决于原始文档，不承诺所有格式均可完全无损转换。

## 技术栈

React、TypeScript、Vite、Tailwind CSS、shadcn/ui 风格基础组件、Lucide Icons、React Router、Vitest 和 React Testing Library。项目使用 Hash Router 以适配静态站点；当前不需要 Python 服务。

PDF 解析和渲染使用固定版本的 Mozilla [`pdfjs-dist` 6.5.438](https://github.com/mozilla/pdf.js/releases/tag/v6.5.438)（Apache-2.0），主模块和解析 Worker 均使用同一依赖中的 `legacy` 兼容构建。`legacy` 表示转译及兼容支持，不是旧版 PDF.js；支持范围以 [PDF.js 官方说明](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions)为准。

PDF 生成使用固定版本 [`pdf-lib` 1.17.1](https://github.com/Hopding/pdf-lib/tree/v1.17.1)（MIT），仅在开始生成时动态导入；安装文件及依赖由 npm 锁文件管理，不使用 CDN。它的页面复制不保证完整保留所有文档级结构。

Worker 通过 Vite `?url` 资产导入生成本地构建地址。CMaps、标准字体、WASM 和 ICC 资源从同版本依赖提供，保留相应许可证，开发服务器与生产构建使用同源版本目录。不依赖 CDN，也不关闭解析 Worker 来绕过加载问题。文档二进制数据直接交给 Worker，不通过网络 URL 加载用户文档。

## 本地安装与运行

最低要求 Node.js 22.13.0（与 PDF.js 及 `package.json` 的 `engines` 一致）；推荐使用 Node.js 24 和 npm 11，与本地验收和 CI 环境保持一致。

```sh
npm ci
npm run dev
```

访问开发服务器输出的地址。Vite 的基础路径固定为 `/PageNest/`，开发地址通常为 `http://localhost:5173/PageNest/`。

```sh
# 类型检查、代码风格、自动化测试、生产构建与公开文件候选审查
npm run check

# 也可以分别执行
npm run typecheck
npm run lint
npm test
npm run test:pdf-engine
npm run test:pdf-export
npm run build
npm run audit:files

# 本地预览生产构建
npm run preview

# 检查运行时依赖的已知漏洞（需要访问 npm registry）
npm audit --omit=dev --audit-level=moderate
```

`npm test` 以非交互方式运行前端测试、真实 PDF 引擎与导出测试和隔离 Git 仓库安全回归测试。`npm run test:pdf-engine` 使用人工生成、无私人内容的 PDF 验证 PDF.js 的真实解析和页面渲染；`npm run test:pdf-export` 真实调用 pdf-lib 后使用 PDF.js 及原生 Canvas 验证文字、图片、矢量、顺序、旋转和生命周期，不只检查模拟页数。`npm run test:security` 可单独运行安全回归测试。测试 PDF 二进制、日志和 `dist/` 均只在本地保留，不应提交。

浏览器验收应分别运行开发服务器和 `npm run build` 后的 `npm run preview`，访问 `/PageNest/#/pdf-editor`，核对真实 PDF 导入、多选、删除、拖拽排序、旋转、撤销重做、多文件切换、横纵与原始旋转页面、懒加载、移除、异常提示及主题。生产预览还应检查 Worker、JS、CSS 和 PDF.js 辅助资源均从 `/PageNest/` 下加载，深链接刷新正常且没有文档上传请求。

导出验收使用人工生成、带明显来源标记的 PDF：对三份文档分别编辑后调整文档顺序合并，下载重导并核对每页来源、内容和方向；另测非连续选页、12 页范围拆分、24 页每 5 页拆分及各份结果。补验 100 页样本、浅深主题以及 1366×768、1920×1080、2560×1440 布局；检查 Network 中 pdf-lib 动态模块和同源 Worker 资源，不应出现文档上传或持久化。

为修复构建工具链的已知 glob 复杂度漏洞，项目暂时将 `@typescript-eslint/typescript-estree` 的 `minimatch` 局部锁定为 `11.0.7`；上游发布包含修复的版本后可移除此 override，再执行完整检查与依赖审计。

## 代码组织

页面、共享 UI、导航布局、主题状态、文件状态、功能配置、类型和本地引擎接口分别组织在 `src/` 的独立模块中。PDF 工作区独立管理二进制数据、解析任务和渲染资源，不扩展原有全局元数据状态的职责。新增工具应添加页面与功能配置，并接入既有路由和布局；避免在单个组件中堆叠整个工作站。本地引擎接口仅定义连接边界，不会在本阶段主动连接本地服务。

## 隐私与仓库审查

私人样本应放在 `local-data/`，临时文件放在 `temp/`，生成结果放在 `outputs/`，日志放在 `logs/`。这些目录以及本地代理约束、凭据、缓存、依赖和构建产物均被忽略。

`npm run audit:files` 分别检查 Git 暂存区实际 Blob 内容，以及工作目录中已追踪文件和未被忽略的新增候选文件。已经被追踪或被强制暂存的文件即使匹配忽略规则，也会接受检查。发现禁传路径、可疑凭据或非预期二进制文件时返回失败；报告仅包含文件路径、扫描来源和问题类别，不打印命中的敏感值。它是启发式辅助审查，不能证明文件绝无私人信息；上传前仍需人工审核实际暂存区 diff。

人工生成的文档测试样本仅允许在 `tests/fixtures/synthetic/`、`test/fixtures/synthetic/` 或 `src/test/fixtures/synthetic/` 中，经人工确认无隐私后再考虑提交。真实文档和 OCR 输出不得进入仓库。

提交前逐项检查：

```sh
git status
git diff
git diff --cached
git diff --cached --check
git ls-files
git check-ignore -v AGENTS.md
npm run audit:files
```

忽略规则无法保护已追踪文件。只应按审核通过的具体路径暂存，不应无差别暂存整个目录，不得强制添加被忽略文件。未经明确批准，不执行远程推送、PR、Release、仓库设置修改或发布。

## GitHub Pages 部署

正式站点：[PageNest](https://ZZH-0427.github.io/PageNest/)。本地版本的更新不代表已经发布到正式站点。

- `vite.config.ts` 使用 `base: '/PageNest/'`；Hash Router 形成 `/PageNest/#/...` 路由，刷新工具页面时无需服务端回退配置。
- PDF.js Worker 和辅助资源随生产构建提供，路径包含该子目录，无需第三方 CDN 或后端服务。
- `checks.yml` 对目标为 `main` 的 Pull Request 执行类型检查、lint、测试、候选文件审查、生产依赖审计和构建。
- `deploy.yml` 在代码进入 `main` 后复用同一套检查；全部通过才上传 `dist/` 并部署 Pages。构建产物由 Actions 生成，不提交到 Git。
- 检查任务仅有 `contents: read`；仅部署任务具有 `pages: write` 和 `id-token: write`。

Pages 发布来源应设为 Settings → Pages → Source → GitHub Actions。建议保护 `main`、要求 PR 审核和 Checks 成功；如需每次上线再确认，可为 `github-pages` 环境配置审核人。工作流本身不能替代分支保护和人工审核，调整这些远程设置需要另行授权。

GitHub Pages 仅托管静态前端，无法运行 Python / FastAPI 服务。Phase 3A 只在本地开发与验证，源码和 UI 审核通过并取得明确授权之后，才能暂存、提交、推送或发布。
